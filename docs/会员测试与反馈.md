# 星空 Codex · 会员测试与问题反馈

当前测试版本：**2.6.0-rc.4**（插件显示 `2.6.0-rc.4+codex.20260908`）。欢迎用真实任务检验操作指引与工作流。先选一项可核对结果的任务，不要直接将未经审核的文案、采购结论或广告文件用于正式业务。

## 如何领取测试资格

1. 星球私信坚哥：**Codex 测试 + Windows/Mac + 想测试的板块 + 是否有产品资料/数据服务**。
2. 收到安排后从本仓库 Releases 下载对应 ZIP，先看 `00-使用说明.html`，运行“申请授权”。
3. 将 **产品版本 + 平台 + 32 位本机申请码** 私发坚哥，领取该版本授权；不将完整授权码发到评论区、Issues 或群里。
4. 安装、体检并重开官方 Codex，在独立产品项目里新建任务。所需 Codex 账号、模型额度和 MCP 服务由测试者自己准备，测试资格不代表包含这些第三方费用。
5. 完成测试或遇到卡点按下方格式反馈。不需要“好评”；安装失败、流程跳步、说明看不懂都是有效反馈。

安装/更新授权期限由坚哥逐人确定。已安装内容到期后仍可使用。固定版本试用不推送新版；会员测试需作者明确登记，按原期限获取更新，操作见 [会员更新说明](会员更新说明.md)。测试资格不自动承诺后续所有版本和服务的长期权益。

## 这轮优先测试什么

| 测试项 | 操作与观察 | 应得到什么 |
| --- | --- | --- |
| Win/Mac 安装更新 | 首装或 rc.1 升级；Mac 保留本地时区，先用普通入口 | 授权成功、版本正确、36 个 Skill、本地体检；出错有指引 |
| 新任务加载 | 重开 Codex，在产品项目新建任务，输入“启动星空。先核对实际插件版本和工具，不抓取商品” | 实际加载 rc.4；区分配置存在、服务可达、认证通过和工具可调用 |
| S1 指导与报告 | 选择一路选品流程，按工作卡推进 | 九步指引；开头有本产品图片、是否可做、依据和限制；演示或待补数据不当通过 |
| S1→S2 交接 | S1 达到允许交接状态 | 下一步、模型建议、真实交接文件与完整口令，同产品项目新建任务提示 |
| S2 竞品与导出 | 要求 20 个同款/同类候选，确认池后观察 | 可复制 ASIN 清单、下载/保存指引，确实停下等待；不沿用 5 个种子直接写文案 |
| S2 清洗与文案 | 放回平台原始 XLSX/CSV 后继续 | 核对文件、来源、覆盖再清洗，分类确认后写文案；MCP JSON 不代替用户导出表 |
| 说明与 MCP | 照包内四份说明配置启动 | 知道上传什么、输入什么、得到什么；优惠渠道与 API 配置分清 |
| 其他板块 | 任选视觉、广告或巡检任务 | 记录输入、输出、遗漏和下一步指引，不要求一次跑完整条链 |

真实候选不足 20 时，应报告搜索证据、缺口和影响，获得你的明确确认后才调整范围，不编造 ASIN 或用重复父体凑数。

## 提交与跟进

- 星球会员直接私信坚哥；也可在 [GitHub Issues](https://github.com/wenjiany312-hub/starsky-amazon-codex-releases/issues/new?template=bug_report.md) 提交**已脱敏**问题。
- 公开 Issues 全网可见。不上传授权码、`license.json`、API Key、完整配置、账号登录信息及客户/店铺隐私。
- 作者核对后按“待复现 → 已确认 → 处理中 → 待复测 → 已关闭”记录；修订后在新版本、新任务复测，保留版本与模型信息。
- 不要求一次测完全部阶段，不保证每项建议都会实现。优先反馈影响安装、数据真实性、流程顺序和实际使用的问题。

当前 rc.4 Mac 实机更新、两平台新任务加载和完整 S1/S2 实跑仍待验收；自动化测试通过不等于模型在每个新任务中都会正确执行工作流。
