# 星空 Codex 2.6.0-rc.10 · S1–S4 昨夜至今 + S5 六项落地

相对已发布的 rc.8：把昨晚到今天刚截止的 S1–S4 优化收进本版，并补齐 S5 可收费交付的六项。Windows/macOS 共用业务载荷与会员规则，保持 Pre-release。内部 rc.9 未单独公开发。

## 本次变化

- **S1–S4 一夜迭代一并发布：**一步一卡、S2 可见报告、S3 套图投喂与视频 1/2/3、S4 广告课堂与流量看板、SIF 本地中转、阶段交接口令。已装 rc.8 的会员一次升到本版即可。
- **S5 接入闸门：**第 1 步先报领星 OpenAPI / 亚马逊 SP-API（只要 LWA，不要 AWS keys）/ 文件投喂三路状态。没有实时接口不准假装日常优化；只有报表时标明降级快照。
- **广告知识库随包：**安装写入 `ads_knowledge_base`。S4 拟策略和 S5 诊断可引用 KC 卡号。知识库不是广告 API，不改价、不暂停、不加预算。
- **R0 数据卫生：**分页截断可见、缺数不是 0、finding 含店铺/站点/原生广告 ID。薄样本（例如点击很少、0 单）只出观察信号，禁止写成“纯浪费”或直接下暂停令。
- **全店账本分开：**默认 `~/.starsky-codex/ops_workspace`，不跟某个新品的 S1–S4 测试夹混写。
- **一条广告异常闭环：**补 ID → 原因树入口 → 保持/观察/调整，等你审核。自动化只到诊断和建议（L1）。Amazon Ads API 写操作本版关闭。
- **发布前脱敏：**公开包扫描授权码、密钥、本机路径和学习会话；命中即停发。

## 这一次怎么升级

**已装 rc.4 且已登记的有效会员：**进入星空业务时如提示新版，保存工作后运行安装包里的“检查新版”。不要下载 Source code。

**rc.1–rc.3 用户：**旧更新器没有会员凭证。请直接下载本页对应 Windows/macOS ZIP，完整解压，运行新包“安装与更新”。已登记会员会读取原激活记录并核验，无需另领 rc.10 新码。

看到 `安装完成：2.6.0-rc.10+codex.20260910` 后，完全退出并重开 Codex，在原产品项目中新建任务核对版本。产品文件、领星配置和原 MCP 密钥保留。本机若已有非星空受管的广告知识库目录，安装器会拒绝覆盖。

## 验证情况

构建前完成 S5 闸门/工作流/效率交付/SIF 等回归；发布包另做脱敏扫描。两平台仍共用一份加密业务载荷。

以上不代表用户设备已经完成升级。Mac 实机更新、新任务完整业务执行与实际 Token 节省尚待验证。安装包仍需要官方 Codex 与 Python 3.11+。
